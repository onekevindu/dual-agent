# Dual-Agent

先明确用户要看到什么结果、用什么证据验收，以及谁负责交付。把实现方法留给实际执行的 Harness。

## 谁来做

- **Codex + agy** 是日常默认搭配。Codex 界定目标、给出关键约束、审查实际改动并独立验证。agy 对照源码核验假设，自主使用常规工具完成实现和自检。若事先解决一个疑点能避免大量返工，可以先做只读核验；其余核验随执行完成。返工尽量续接原子会话。
- **只用 Codex / 只用 agy** 时，直接由指定宿主负责实现和验收，沿用当前选定模型。省去外部派工、双模型选型和交接。宿主可在授权范围内使用自己的能力；用户指定单会话或禁止并行时也遵守。若目标宿主未接入，说明实际可执行的范围。
- **只讨论** 时，全程只读，以证据、分歧和待定取舍收尾。用户要求双方评审才启动双方。双会话讨论沿用当前主控，子方默认个人 agy 的 `gemini-4-hydrogen-xhigh`，用户点名的模型优先。
- **双会话首次开发由用户选模型**。先确认当前主控模型，再用目标通道的 `agy models` 取得执行模型候选。用户已点名或在本会话已选定的那一项直接沿用。对尚未选择的项，给出推荐及理由，等用户选定再启动。可用的 `gemini-4-hydrogen-xhigh` 是默认推荐项，仍由用户确认。
- **用户明确说“模型你来选”时**，主控在受托范围内直接选型，用一句话说明所选模型和任务依据。只委托选 agy 模型时，委托仅适用于 agy。主控模型以当前会话实际生效值为准，需要手动切换时说明操作。同会话返工复用选择。启动外部 agy 时按需读取[调用说明](references/agy-launch.md)。

## 怎么选工具

Codex 派工时由 Codex 判断执行方式，单宿主时由当前宿主判断。普通执行足以完成任务时直接推进。需要为 agy 推荐模式时，先查当前通道的 `agy --help`（同版本同会话可复用），从实际可用的模式、参数和子命令中选最贴合当前瓶颈的一项。涉及 slash 命令时，再按实际入口核对交互命令菜单、print 帮助或本机更新记录。新版增加的能力也参与选择。

复杂命令若涉及明显额外配额、多个执行会话或执行范围变化，且超出已有授权，先用一句话说明推荐的命令、它能解决什么、主要代价，以及普通执行是否可行，让用户选择后再启动。用户已明确指定或授权该操作时直接执行。受托选模型只覆盖模型选择。

以下是两种可选能力：

- **`/swarm` 蜂群**让 agy 协调多个独立会话并行工作，成员通过共享看板交换发现、进度和阻塞。主控权衡并行和共享信息的收益，以及各成员消耗的配额与整合成本。涉及多个模块的改动也可能一次检索就能定位。
- **`/boost`** 可以集中额外推理力量处理同一个难点。例如，两种死锁解释都符合现有日志时，独立推演可能有帮助；若线程栈已证实锁顺序，直接验证修复即可。

主控选中某项能力后，通过当前入口支持的命令或原生工具显式启用，把具体问题、证据、边界和验收条件一并交给执行方。采用普通执行时，派工提示直接写任务，省去备选命令清单。选用 Orchestrator 时继续沿用所选模型，由它安排内部执行；主控按同样原则选择额外能力。

需求有歧义时先尝试从项目取证，只把会改变交付的取舍交给用户。长任务给出可检查的完成条件，持续目标按宿主权限和用户授权启用。

区分模型可调用工具、用户可输入的交互命令、无头入口可接受的请求。主控若掌握合适且已确认支持的入口，可在启动时使用；仅在交互界面可用时，可提示用户具体操作，同时用可用工具继续独立工作。通过实际调用结果确认发生了什么。任务中途有旁问时，保留主任务的负责人、进度和完成条件。

## 交付

保护现有未提交改动。除非用户本轮明确要求编写单测，主控和所有执行方均禁止新增 `src/test/**` 或在 `pom.xml` 添加测试依赖；派工时把这条写入边界。选择能验证具体结果的检查，例如编译、运行态复核或对数据结构的检查。只回传关键差异、验证证据和未解决的问题；主控核对结果后再交付。
